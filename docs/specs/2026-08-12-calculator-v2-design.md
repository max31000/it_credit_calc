# Калькулятор льготной ипотеки v2 — дизайн переработки

Дата: 2026-08-12. Статус: фазы 1–2 реализуются сразу, фаза 3 (трекер) — после ответов владельца.

## Мотивация

Проблемы v1 (подтверждены чтением кода):

1. **Слёт не влияет на симуляцию.** `series` считается по льготной ставке весь горизонт;
   слёт живёт только в отдельных метриках `slipScenario`. Пользователь ожидает: при слёте
   стратегия «копить» немедленно вносит все накопления в досрочку, ставка меняется на рыночную,
   и дальше жизнь продолжается по новым условиям.
2. **После погашения долга деньги «исчезают».** В стратегии А (досрочное погашение) после
   обнуления долга freeMonthly никуда не идёт (savingsA всегда 0). Это искусственно завышает
   выгоду стратегии Б на длинных горизонтах — калькулятор «продаёт» Б.
3. **Налоговые вычеты асимметричны.** Возвраты зачисляются только в накопления Б; стратегия А
   не получает ничего, хотя в реальности возврат пошёл бы в досрочку.
4. **Порядок вычетов.** Возврат по процентам считается от полной зарплатной базы, игнорируя
   уже применённый имущественный вычет. Правильно: вычеты последовательно уменьшают одну
   налоговую базу года (сначала имущественный, затем процентный), суммарный возврат ≤ НДФЛ года.
5. **UI перегружен и агитирует за Б** («Победитель ✓», преимущество победителя и т.п.).
   Нужен нейтральный инструмент, отвечающий на конкретные вопросы.
6. **Шкалы неточные**: нет прямого управления суммой кредита, крупные шаги слайдеров.

## Фаза 1 — движок v2

### Единый симулятор

`simulateStrategy(params, opts)` — один проход по месяцам, опции:

- `strategy: 'prepay' | 'save'` — А (досрочка с уменьшением платежа) или Б (минимум + инвестиции);
- `slipMonth: number` — 0 = без слёта;
- `dumpSavingsAtSlip: boolean` — вносить ли накопления в долг в момент слёта (для варианта «наивный слёт»).

Правила симуляции:

- До слёта ставка льготная; в месяц слёта ставка становится рыночной
  (`keyRate − bankDiscount + 1.5`), аннуитет пересчитывается на остаток срока.
- Стратегия save при слёте (если `dumpSavingsAtSlip`): `pay = min(savings, debt)`;
  `debt −= pay; savings −= pay`; аннуитет пересчитывается по остатку.
- После обнуления долга **обе** стратегии инвестируют весь freeMonthly под depositRate.
- Если freeMonthly < обязательного платежа — платёж всё равно вносится (это обязательство),
  инвестиций нет; UI предупреждает.
- Налоговые вычеты (если задана зарплата), в конце каждого года, отдельно для каждой стратегии
  (проценты у них разные):
  - База года = 12 × зарплата. Сначала расходуется остаток имущественной базы
    (min(2 000 000, цена)), затем процентная база (фактические проценты года, суммарный лимит
    базы 3 000 000 ₽).
  - Возврат = НДФЛ(база года) − НДФЛ(база года − использованные вычеты), по прогрессивной
    шкале 2025 (13/15/18/20/22 % на ступенях 2.4/5/20/50 млн).
  - Возврат у save-стратегии → в накопления; у prepay-стратегии → в досрочку
    (после погашения долга → в накопления).

### Варианты расчёта в `calculate()`

| Вариант | Когда считается | Зачем |
|---|---|---|
| `prepay` базовый (без слёта) | всегда | линия А, сравнение подходов |
| `save` базовый (без слёта) | всегда | линия Б, payoffMonth, доход от инвестиций |
| `prepay` со слётом | slipMonth > 0 | линия А при слёте |
| `save` со слётом + внесение | slipMonth > 0 | основной сценарий слёта |
| `save` со слётом без внесения | slipMonth > 0 | цена «ничего не делать при слёте» |

Отображаемые серии: при slipMonth > 0 — слётные варианты, иначе базовые.

### Новые выходные метрики (insights)

- `payoffMonth` — первый месяц, когда накоплений save-стратегии (базовый вариант) хватает,
  чтобы закрыть долг целиком; null если не в горизонте.
- `investmentIncome` — проценты, заработанные на накоплениях за горизонт (базовый save).
- `advantageSaveVsPrepay` — разница netWorth «копить» − «гасить досрочно» на горизонте
  (в отображаемом сценарии, т.е. с учётом слёта, если он задан).
- При slipMonth > 0:
  - `slipLoss` — netWorth(базовый save) − netWorth(слёт+внесение): сколько стоит слёт;
  - `dumpBenefit` — netWorth(слёт+внесение) − netWorth(слёт без внесения): сколько экономит
    внесение накоплений при слёте;
  - платежи после слёта с внесением и без (как раньше).
- `safetyPoint` и `slipAnalysis` сохраняются (по базовому save-варианту), семантика прежняя.

Существующие числовые инварианты тестов (§9 ALGORITHMS.md) остаются верны для базовых
вариантов; тесты расширяются на слёт-варианты и симметрию вычетов.

## Фаза 2 — UI

Структура страницы:

1. **Header** — нейтральный подзаголовок («посчитайте платёж, точку полного погашения и цену
   слёта с льготной программы»).
2. **Параметры** — секция с точными шкалами:
   - Стоимость квартиры: слайдер 1–30 млн, шаг 50 тыс + NumberInput без ограничения сверху.
   - Первоначальный взнос: слайдер в ₽ (0–цена, шаг 10 тыс) + NumberInput + подпись с %.
   - **Сумма кредита: собственный слайдер + ввод**; движение меняет взнос (цена фиксирована).
   - Остальные поля получают NumberInput рядом со слайдером (единый компонент SliderInput).
3. **Сценарий слёта** — как раньше (месяц слёта, ключевая ставка, дисконт), без изменений сути.
4. **Выводы** — карточки с прямыми ответами:
   - платёж и переплата по графику; налоговые вычеты;
   - «полностью закрыть ипотеку сможете через N лет M мес» (payoffMonth);
   - «за горизонт инвестиции принесут X» (investmentIncome);
   - «разница подходов на горизонте: Z в пользу …» — нейтрально, без «Победитель ✓»;
   - при слёте: «слёт обойдётся в X», «внесение накоплений при слёте экономит Y»,
     «платёж станет P₁ (с внесением) / P₂ (без)», точка безопасности.
5. **Графики в табах** (убирает простыню из трёх графиков):
   - «Капитал» — netWorth обеих стратегий (с изломом в месяц слёта);
   - «Долг и накопления» — debt/savings, отмечена точка полного погашения;
   - «Если слёт» — платёж-после-слёта по месяцам слёта + льготный уровень + точка
     безопасности (график из v1, семантика сохранена, подписи упрощены).
6. **Методика** (аккордеон) — без «Рекомендаций» и победителей: формулы, допущения,
   порядок вычетов, дисклеймер «не инвестиционная рекомендация».

Терминология: «Гасить досрочно» и «Копить» вместо «Стратегия А/Б» (буквы остаются
в подписях графиков как краткие метки, если нужно).

## Фаза 3 — трекер ипотеки (дизайн, требует решений владельца)

По образцу bonds: .NET 8 minimal API + MySQL + JWT, авторизация через Telegram Login Widget
(HMAC-проверка `SHA256(bot_token)`, allowlist по `Telegram:OwnerId`), фронт — страница Login
с виджетом, zustand-store токена, деплой на VDS за portal-shell (`/credit_calc/api`).

Данные: таблица `mortgages` (user_id, параметры кредита, дата взятия, актуальный остаток,
история корректировок/платежей). Калькулятор получает режим «трекинг»: подставляет актуальный
остаток и показывает «осталось N лет M мес, долг X».
